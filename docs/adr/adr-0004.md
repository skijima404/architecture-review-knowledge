# ADR-0004: Unifying Causal Edge Vocabulary Across Markdown and Graph Representations

## Status
Accepted

## Context

In this project, a Failure Backcasting Map is modeled using three main node types:

- Success Criteria (`sc-xxx`)
- Symptom (`rf-xxx`)
- Root Cause (`rc-xxx`)

Initially, causal relationships were discussed separately for:

- Markdown frontmatter fields (see ADR-0001)
- GraphDB edge labels (see ADR-0002)

ADR-0001 introduced relationship names such as `explained_by`, `explained_by_symptom`, `caused_by`, `triggers_symptoms`, and `triggers_root_causes` for use in YAML frontmatter. ADR-0002 then defined a set of causal edge labels for GraphDB:

- `triggers`
- `triggered_by`
- `threatens`
- `threatened_by`
- `leads_to`
- `leads_from`

Over time, the primary use case has shifted:

- The Backcasting Map is now mostly consumed via Markdown and GenAI memory structures (e.g., LangChain-based pipelines), rather than a dedicated GraphDB.
- Maintaining two similar but different vocabularies for causal relationships (one for Markdown, one for GraphDB) increases cognitive load and the risk of confusion for future maintenance.

To simplify the model and reduce the chance that we forget the naming rules, we want to:

- Use a single causal vocabulary across all representations
- Align Markdown frontmatter fields with the Graph-style causal labels from ADR-0002

## Decision

We adopt the causal edge labels from ADR-0002 as the **canonical vocabulary** for Backcasting Map relationships across **all** representations:

- `triggers`
- `triggered_by`
- `threatens`
- `threatened_by`
- `leads_to`
- `leads_from`

These labels are now used consistently in:

- Markdown frontmatter fields (see `docs/backcasting-map-spec.md`)
- Any GraphDB or graph library representation, if and when it is used
- GenAI memory structures and metadata (e.g., LangChain document metadata or vector-store payloads)

Concretely:

- Symptom nodes use:
  - `triggered_by` for upstream Root Causes or Symptoms
  - `triggers` for downstream Symptoms
  - `threatens` for impacted Success Criteria
- Root Cause nodes use:
  - `leads_from` for upstream Root Causes (symmetric with `leads_to`)
  - `triggers` for downstream Symptoms
  - `leads_to` for downstream Root Causes
- Success Criteria nodes use:
  - `threatened_by` for Symptoms or Root Causes that endanger the criteria

The `docs/backcasting-map-spec.md` file has been updated to reflect this vocabulary and is now the single source of truth for node structure and relationship field names.

ADR-0001 is marked as **Superseded** and retained only as historical documentation of earlier naming experiments.
ADR-0002 remains **Accepted** as the original definition of the causal edge labels, but its scope is extended to cover all graph-like representations, not only GraphDB.

## Consequences

- There is now a single set of causal relationship names to remember and use, regardless of whether we are looking at Markdown, a GraphDB visualization, or GenAI metadata.
- Future tooling (Miro → Markdown converters, LangChain chains, visualization scripts) can rely on the same vocabulary without additional mapping layers.
- Older documents or prototypes that used the ADR-0001-style names (`explained_by`, `caused_by`, etc.) should be treated as legacy and migrated to the canonical vocabulary when touched.
- If we later introduce a physical GraphDB again, its edges can directly mirror the frontmatter fields without extra renaming.
