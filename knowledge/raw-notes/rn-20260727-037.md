# Gateway Quotas and Mesh Rate Controls Protect Different Boundaries

## Note

API Gateway Quotas and Service Mesh Rate controls may coexist because they
protect different boundaries and count different units.

### API Gateway: Consumption Agreement

An API Gateway is the boundary between API Consumption inside a system and the
external world of Consumer organizations or applications.

Its primary control is a Quota derived from an API Consumption Agreement:

- how much a Consumer is expected or entitled to use;
- which Plan or API Product applies;
- how usage is divided among Consumers; and
- how one defective or excessive Consumer is prevented from harming another.

Rate Limiting may be implemented with the same product mechanism, but technical
Backend protection is a secondary use. The primary meaning is contractual and
governance-oriented.

### Service Mesh: Actual Backend Demand

The Service Mesh sees the requests that actually reach a Backend.

An Integration Layer can amplify one external request:

```text
API Gateway: 1 request
  -> Camel fan-out: 10 requests
  -> Service Mesh: 10 requests
  -> Backend API: 10 requests
```

Several external Contracts can also converge on one Backend:

```text
/users:    3 requests --+
                        +-> Shared Backend: 6 requests
/products: 3 requests --+
```

The API Gateway sees Consumer-facing Contracts. The Service Mesh sees
post-aggregation, post-transformation, and post-routing demand. Backend Rate,
Concurrency, Timeout, Retry, and Circuit-Breaker controls therefore belong
close to the Backend.

### Parallel Controls

The two controls are not a fixed sequence. Either may reject first depending
on:

- Quota and Rate parameters;
- Time Windows;
- Fan-out;
- Retry;
- Concurrency;
- route convergence; and
- Backend Capacity.

This is a tuning problem rather than proof that one layer owns all traffic
control.

The practitioner does not prescribe a universal Telemetry checklist. Required
observations are derived from the External Contract, Internal Contracts, and
every ingress path connecting them.

## Questions

- How should Contract usage and Backend demand be correlated in a given design?
- Which parameter changes prevent one Consumer from consuming shared Capacity?
- When does changing a Gateway Quota conceal rather than resolve a Backend
  Capacity problem?
