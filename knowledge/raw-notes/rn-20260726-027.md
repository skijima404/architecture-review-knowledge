# Responsibility Concentration Is Observed Across Design, Code, Runtime, and Work

## Note

This note records an interview response to a question in `rn-20260726-008` and
continues `rn-20260726-026`.

After implementation begins, responsibility and complexity concentration can be
examined through several evidence surfaces.

## Runtime and Infrastructure

The practitioner wants Observability that can expose:

- actual runtime topology;
- request and access volume;
- concurrent HTTP connections;
- database connection counts; and
- service-mesh telemetry, including data available from platforms such as
  Istio.

These signals can show whether the implemented dependency and load shape matches
the design-time Context Map and whether a particular service or data dependency
has become a concentration point.

## Implementation and CI

Before production operation, CI static analysis and code-complexity evidence may
expose early signs that responsibilities or decisions are accumulating in one
implementation area.

These implementation signals are compared with the workshop's Context Map and
Boundary reasoning. They provide later evidence for validating or revisiting the
initial hypothesis; they are not treated as a separate Architecture Review
method in this note.

## Work and Communication

For Agile delivery, the practitioner also examines socio-technical evidence:

- communication paths between the Product Owner and development teams;
- the nature and content of those interactions; and
- trends in Product Backlog Items.

Responsibility concentration may therefore appear in runtime traffic, code,
data access, backlog shape, or repeated knowledge transfer and decision paths.
No single signal proves a boundary problem; the evidence must be compared with
the intended responsibility and Context Map.

## Questions

- Which topology, load, and connection patterns indicate inappropriate
  concentration rather than legitimate demand?
- Which communication-path and backlog patterns suggest a boundary problem?

## Next Steps

Define concrete observations for the runtime, implementation, and
socio-technical evidence surfaces.
