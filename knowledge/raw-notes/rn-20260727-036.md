# Authorization Is Enforced Where the Required Knowledge Exists

## Note

The practitioner applies Authorization in layers. A control is placed where the
Knowledge required for the decision is available.

### Contract-Level Authorization

An OAuth Scope or similar decision may be made from:

- the requested URL;
- the HTTP operation;
- Token Claims; and
- the published API Contract.

API Gateway or Service Mesh controls can Accept or Reject these requests
without loading Domain state.

### Object-Level Authorization

Broken Object Level Authorization (BOLA) requires deciding whether a Subject may
perform an operation on a specific Resource.

For example:

```text
Subject: skijima
Resource: /api/users/12345
```

The decision may require Resource Ownership, Tenant membership, delegation,
Domain state, or other Business relationships. API Gateways and Service Meshes
normally lack this Knowledge. The Backend API therefore performs the
authoritative object-level decision in most cases.

A Service Mesh may exceptionally enforce BOLA when the decision is a simple,
complete comparison between Request data and Token Claims, such as a Path
identifier that exactly matches the authenticated Subject. The practitioner
expects such cases to be uncommon.

Passing an outer Authorization layer never substitutes for the Backend's
Business Authorization.

### Business Logic Leakage

Domain Business Logic belongs in the Backend. Reimplementing it in an
Integration Layer creates a risk that:

- the Backend and Integration copies diverge;
- one copy is not updated;
- a new Integration path omits the Rule;
- testing and incident analysis miss the actual decision location; or
- different teams change the same Business Invariant independently.

The most frequently observed mechanism is duplicated Rules followed by an
update omission.

Temporary leakage may be accepted as a transition measure, but it remains a
known risk and an explicit correction target.

### Public Disclosure as an Investigation Example

Source `src-20260727-004` describes a YouTube Video Builder endpoint that
accepted a caller-provided Channel ID and uploaded an unlisted video to a
Channel the caller did not own.

The disclosure demonstrates a missing authoritative Ownership check on that
write path. It does not disclose enough internal architecture to prove that a
Backend and Integration Layer contained duplicated Rules or that one copy had
become stale. Treat that explanation as an Architecture hypothesis, not as a
verified root cause.
