# North-South Integration Assigns Responsibility by Semantic Depth

## Note

The practitioner models a synchronous North-South API flow as a sequence of
Solution Layers:

```text
External Consumer
  -> WAF / WAAP
  -> API Gateway
  -> Integration Layer such as Camel
  -> Service Mesh
  -> Backend API
```

The placement principle is the depth of Semantics required to make the
decision.

### WAF and WAAP

WAF and WAAP handle Security controls that do not require API-specific or
Domain-specific Business Semantics. They may inspect HTTP characteristics, but
they should not need to understand the Business meaning of an individual API
operation.

### API Gateway

The API Gateway handles the boundary between an API Consumer and the providing
organization or system. Its responsibilities may include:

- API Management and organizational Governance;
- Routing that can be decided from the published URL or Contract;
- Consumer identification;
- API Consumption Agreements and Quotas; and
- other controls based on the published API Contract.

### Integration Layer

An Integration Layer such as Camel may provide:

- BFF behavior;
- Mashup and Aggregation;
- technical Transformation;
- compatibility between External and Internal Contract versions; and
- Routing across Backend Contracts.

It must not become the authoritative owner of Domain Business Logic.

### Service Mesh

The Service Mesh observes traffic immediately before or between Backend
Services. It is therefore suitable for technical Backend protection such as:

- mTLS;
- Rate and Concurrency control;
- Timeout;
- Retry;
- Circuit Breaking; and
- other controls based on actual Backend traffic.

### Backend

The Backend owns Domain Business Logic, Business Invariants, state transitions,
and decisions that require Domain Data.

The exact division among products permits Trade-offs. The layering is a
responsibility template, not a claim that every product deployment must contain
all layers. Moving a responsibility remains acceptable only while the receiving
layer has the Knowledge and authority required to perform it without duplicating
Domain decisions.

## Questions

- Which technical transformations can remain in the Integration Layer without
  becoming Business Logic?
- Which deployments can safely omit one of the layers?
- How should temporary responsibility leakage be identified and retired?
